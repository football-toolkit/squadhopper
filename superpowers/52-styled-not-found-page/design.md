# Design: style the 404 page like the home page

Issue: #52 (Task). Branch and change key: `52-styled-not-found-page`.

## Intent

Any unknown URL shows Next.js's default 404 page, which doesn't use the app's look. The app gets its own 404 page in the same frame as the home page, with a clear way back home, and the URL still returns a real `404`.

## Goals

Issue #52's "Done when" list:

- [ ] An unknown URL shows the 404 page in `PitchLayout` with `AppHeader`, with the heading, the lead text and the main button
- [ ] "Back to home" is a link to `/` styled as the main button, built from shadcn/ui's Button
- [ ] The page has its own title, built from the app name constant
- [ ] `curl -I` on an unknown URL against `npm run build && npm run start` returns `404`
- [ ] The page uses only theme tokens and Tailwind's default scales
- [ ] The tests and the design guide are updated
- [ ] `npm test`, `npm run lint`, `npm run typecheck`, `npm run format:check` and `npm run build` pass
- [ ] The repository owner reviewed the PR's Vercel preview

Only the owner can do the last item, once the PR exists.

## Non-goals

- An error page (`error.tsx`, `global-error.tsx`).
- Calling `notFound()` from any route (none needs it yet).
- `global-not-found.js`: experimental, meant for several root layouts or a dynamic root segment, and it skips the root layout.

## Constraints, checked against the docs

- **Next.js 16.4.3** (`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/not-found.md`, matching https://nextjs.org/docs/app/api-reference/file-conventions/not-found): the root `app/not-found.js` handles every unmatched URL and renders inside the root layout, so it gets the `dark scheme-dark` classes and both fonts. It may export `metadata`. Next.js returns `404` only if the not-found UI is ready before streaming starts (`loading.md`, "Status codes"), and adds `<meta name="robots" content="noindex">` itself. So the file stays synchronous: no `await`, no `headers()`/`cookies()`, no `<Suspense>`, and no root `loading.tsx`. With `cacheComponents: true`, it then stays static.
- **shadcn/ui Button, base-nova style** (https://ui.shadcn.com/docs/components/base/button): "Do not use `<Button render={<a />} nativeButton={false} />` for links", because Base UI's Button always sets `role="button"`. Use `buttonVariants` on a link instead. Base UI's docs (https://base-ui.com/react/components/button) say the same. `npx shadcn add button` writes `src/components/ui/button.tsx`, exporting `Button` and `buttonVariants`. Its default variant is `bg-primary text-primary-foreground hover:bg-primary/80`, `rounded-lg`, with a grey focus ring (`focus-visible:ring-ring/50`). Its default size is `h-8 px-2.5 text-sm font-medium`.
- **`cn` merges Tailwind classes** (the `cn` package is a clsx + tailwind-merge replacement): checked, `cn("h-8 text-sm font-medium px-2.5", "h-12 text-lg font-extrabold px-8")` gives `h-12 text-lg font-extrabold px-8`. But `buttonVariants()` is a cva function, and cva appends `className` without removing conflicts (the generated `Button` wraps it in `cn()` for this reason). So the link uses `cn(buttonVariants(), "…")`, with `cn` from `@/lib/utils`, and the defaults are overridden cleanly.
- **Design guide:** volt only for pitch lines, highlighted words and the main button. Colors and fonts from tokens, sizes from Tailwind's default scale, no bracket values in the code we write. `font-heading` always with `italic font-extrabold` and uppercase.
- **App name rule:** the title uses `APP_NAME` from `src/lib/app-name.ts`.

## Design

### `src/app/not-found.tsx`

A synchronous Server Component, the same shape as `src/app/page.tsx`:

```tsx
<PitchLayout header={<AppHeader />}>
  <Card className="…the home page's card classes…">
    <h1 className="font-heading text-4xl leading-none font-extrabold italic uppercase md:text-6xl">
      <span className="text-primary">404</span> <br />
      Page not found.
    </h1>
    <p className="text-sm text-muted-foreground md:text-lg">
      This page doesn't exist or has moved.
    </p>
    <Link href="/" className={cn(buttonVariants(), "…")}>
      Back to home
    </Link>
  </Card>
</PitchLayout>
```

- **Card:** the same classes as the home page's card, copied, so both pages match. (Pulling them into a shared component is left for when a third page needs them.)
- **Heading:** the space before `<br />` makes its accessible name "404 Page not found.", as on the home page.
- **Main button:** `cn(buttonVariants(), "h-12 w-full px-8 font-heading text-xl font-extrabold italic uppercase md:w-auto")` on `next/link`'s `<Link href="/">`, so it's a real `<a>`, with no `role="button"`.
- **Metadata:** `export const metadata: Metadata = { title: \`Page not found · ${APP_NAME}\` }`.

### `src/components/ui/button.tsx`

Generated by `npx shadcn add button`, then `npm run format`. Not hand-edited. The design-system rule doesn't cover its bracket values.

### My calls (the issue doesn't settle these)

- **Button size:** the default `h-8 text-sm` is small for the page's one action. The "Log in" button in the design picture is about 48 px tall with a heading-font label, so: `h-12` (48 px), `px-8`, `text-xl` (20 px, the closest step to the picture's 22 px label; the owner's choice in the design review).
- **Button width:** full width on phones, like "Log in" in the picture, so it's easy to tap. From `md:` it fits its text (`md:w-auto`), because a 640 px wide volt bar on desktop would outweigh the heading. The card centers its children (`items-center`), so the button is centered.
- **Title separator:** "Page not found · " + the app name, with a middle dot.
- **Spacing:** the card's `gap-4` also spaces the button from the lead text, so no extra margin.

## Docs

`docs/reference/design-guide.md`:

- A short "Main button" section after Page layout: what it's for (the page's one main action, in volt), its classes, and an example of `<Link>` styled with `cn(buttonVariants(), "…")`, and why not `buttonVariants({ className })`. A real action (a form submit) uses `<Button>` with the same classes.
- A Do and don't row: style a link that looks like a button with `cn(buttonVariants(), …)` on `<Link>`, not with `<Button render={<Link />} nativeButton={false}>`, because that sets `role="button"` over the link's role.

No ADR: the issue made the choices (root `not-found.tsx`, `buttonVariants` on a link), each following the official docs, and none is costly to undo.
