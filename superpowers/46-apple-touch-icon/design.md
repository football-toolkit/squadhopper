# Design: add an Apple touch icon and a PNG favicon

Issue: #46 (Task). Branch and change key: `46-apple-touch-icon`.

## Intent

The favicon from #38 is only `src/app/icon.svg`. iPhones and iPads ignore it for "Add to Home Screen" and use a screenshot of the page instead, and browsers without SVG favicons, such as Safari before version 26, show a blank square. This change adds the two raster icons that cover them, drawn from the same design.

## Goals

Issue #46's "Done when" list:

- [ ] `apple-icon.png` and a PNG or ICO favicon exist, matching `icon.svg`
- [ ] The page's HTML links all icons
- [ ] On an iPhone, "Add to Home Screen" shows the icon (checked by the repository owner on the preview)
- [ ] `npm test`, `npm run lint`, `npm run typecheck`, `npm run format:check` and `npm run build` pass

Only the owner can do the iPhone item, on the PR's Vercel preview. The PR opens with it unticked.

## Non-goals

- No change to `icon.svg` or to the design.
- No web app manifest, Android icons or maskable icons.
- No icon generated by code (`icon.tsx` with `ImageResponse`), and no new dependency or build step.

## Constraints

- **Next.js 16.4.3 file conventions** (`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/01-metadata/app-icons.md`, matching the current docs at nextjs.org): `favicon.ico` only in the root of `app/`, `icon.(ico|jpg|jpeg|png|svg)` and `apple-icon.(jpg|jpeg|png)` anywhere in `app/`. Next.js reads each file and adds the `<link>` tags, with `type` and `sizes`, itself.
- No one-off colors: the icons reuse the two colors already in `icon.svg`, surface `#141A22` and volt `#C8FF2E`.

## Decisions (agent's calls)

- **The fallback favicon is `src/app/favicon.ico`, not `icon.png`.** Browsers and crawlers request `/favicon.ico` by default, whatever the HTML says, so an ICO answers those requests too. It holds 16, 32 and 48 px images, so the tab, bookmarks and Windows shortcuts each get a crisp size. A second `icon.*` file would also need a number suffix (`icon1.png`), which is less clear.
- **The ICO keeps the rounded corners of `icon.svg`**, so it matches the SVG tab icon exactly.
- **The Apple icon is a full square, with no rounded corners and no transparency.** iOS rounds the corners itself, and it fills transparent pixels with black, which would leave black corners. The pitch keeps its size and position from `icon.svg` (22 of 32 units wide), which leaves the margin Apple's mask needs. Size 180 × 180, as the issue asks.
- **The images are made once from `icon.svg` and committed.** They are rendered with `sharp`, which Next.js already installs, by a throwaway script; the ICO is assembled from PNG images, which every browser that reads ICO supports. Nothing is added to `package.json`. If `icon.svg` changes, the raster icons are redrawn the same way (noted in a new "App icons" section of the design guide, which mentions no icons yet).
- **A unit test pins the files:** `src/app/__tests__/icons.test.ts` reads the PNG and ICO headers and checks the sizes (180 × 180; 16, 32 and 48 px), so a wrong size or a deleted file fails `npm test`.

## Verification

- `npm run build`, then `npm start` and fetch `/`: the HTML has `rel="icon"` links for `/favicon.ico` and `/icon.svg`, and a `rel="apple-touch-icon"` link with `sizes="180x180"`. Each linked URL returns 200 with the right content type.
- Look at the rendered PNGs next to `icon.svg`.
- The owner adds the preview to an iPhone's home screen.
