# Define the visual identity: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Set the "Night pitch" look as theme values and components, restyle the home page as the picture's home screen, and write the design guide and ADR 0014.

**Architecture:** First the theme: color tokens in `globals.css`, the two fonts through `next/font` on `<html>`, and the app name constant. Then the reusable pieces (`Wordmark`, `Pitch`, `PitchLayout`, `AppHeader`) and the favicon. Then the home page, built from them and shadcn's Card. Then the build checks. Docs last: the design guide with the picture, the `AGENTS.md` and how-to links, and the ADR.

**Tech Stack:** Next.js 16.4.3 (`next/font/google`, `app/icon.svg`), Tailwind CSS 4.3.4, shadcn/ui CLI 4.23.0 (`base-nova`, Base UI), Vitest 5 with Testing Library and jsdom, Node 24.

**Spec:** [design.md](design.md). Branch: `38-visual-identity`.

## Global Constraints

- The only custom tokens are the colors (`surface`, `divider` and shadcn's color tokens) and the two fonts. Type sizes, spacing, radius (`--radius` stays `0.625rem`) and shadow use Tailwind's defaults.
- No arbitrary `[…]` values in code written for this change, except `h-[50svh]` in `PitchLayout`. No hex colors in `src/` outside `globals.css` and `src/app/icon.svg`. No Tailwind palette classes (`lime-`, `slate-`, `red-`…).
- Volt (`primary`) only in the pitch lines, highlighted words and the main button. Never links, focus rings (`--ring` is `#9AA4B2`) or borders.
- next/font variables are `--font-inter` and `--font-barlow-condensed`, never `--font-sans` or `--font-heading` (the self-reference trap from #37).
- Both fonts use `display: "block"`. Heading text always pairs `font-heading` with `italic font-extrabold`.
- Phone values below `md`, desktop values from `md:` up.
- The app name appears only in the `README.md` title and `src/lib/app-name.ts`. Copy elsewhere uses the constant.
- Code generated by `npx shadcn add` stays as generated. Run `npm run format` after it.
- Don't commit the reference HTML. Tests go in `__tests__/` next to the code, named after the file.
- Before every commit: `npm test`, `npm run lint`, `npm run typecheck`, `npm run format:check` pass. `npm run build` passes before the PR (Task 4).
- Stage by explicit path only. Every commit message ends with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (the second `-m` below). After each commit, show the owner only `git show --stat`.
- Pushing, editing the issue and opening the PR are not part of this plan. They need the owner's OK.

## Review Focus

These have no unit test, so each is pinned by a verification step in the task named.

- **A narrow phone or a short screen** (360 × 640, 844 × 390, 1280 × 500): the pitch shrinks whole, but not below about 96 px tall, stays centered with equal space above and below, and never touches the card. The grey ends at half the screen, except on short screens, where it grows just enough for the 96 px pitch. Safari on a real iPhone in landscape is the case that broke before. Task 4 lists the sizes. This machine has no browser an agent can drive, so the owner checks them on the preview.
- **The font trap:** a theme font variable that refers to itself makes the page fall back to the browser's font while the build stays green. Task 4 checks the compiled CSS.
- **A flash of the wrong font:** the built CSS must have `font-display:block` for both fonts, and the HTML must preload them. Task 4 checks both.
- **Volt creeping in through generated code:** shadcn's Card or the base layer could use `primary` or `ring` in a way that shows volt. Task 4 searches `src/` and checks `--ring`.
- **A fresh clone, as in CI and on Vercel:** `next/font/google` downloads the fonts during `next build`, so the build needs the network, and the lockfile must still install with `npm ci`. Task 4 runs both from a clean state.
