# Documentation

Everything about this project: what it does, how to use it, and why it's built this way.

These docs follow **[Diátaxis](https://diataxis.fr)** ([ADR 0002](explanation/decisions/0002-structure-docs-with-diataxis.md)). It splits pages into four kinds, because you need different things at different moments:

| | **When you are learning** | **When you are working** |
| --- | --- | --- |
| **Doing** | 📘 **Tutorials**: follow along, step by step | 🛠️ **How-to guides**: solve one specific task |
| **Understanding** | 💡 **Explanation**: why things are the way they are | 📚 **Reference**: exact facts, settings, commands |

## Contents

| 🛠️ [How-to guides](how-to/README.md) | The development workflow, from idea to merge |
| 💡 [Explanation](explanation/README.md) | Design decisions (ADRs) |

Sections get linked here as they're written. Following Diátaxis, there are no empty placeholder pages.

## How these docs are organized

- **Every folder has a `README.md`**: a short overview, a table of contents, and links to where to go next.
- **Lists stay short, about 7 items.** Larger sections are split into subfolders, each with its own `README.md`.
- **File names use kebab-case.** Number prefixes are used only where order matters (tutorial steps, ADRs).
